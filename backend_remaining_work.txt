MODULE 4 — MANAGER APPROVAL
================================================================================

[DONE]    Manager sees pending requests from their department
[DONE]    Manager approves — status changes, balance deducted
[DONE]    Manager rejects — rejection reason mandatory, status changes
[DONE]    Department-level scope restriction for managers
[DONE]    HR Admin can also approve/reject (sees all pending requests)

[MISSING] Manager cannot approve their OWN leave — route to HR Admin
          — PDF says: "A manager cannot approve their own leave — it goes to HR Admin"
          — Current ApproveLeaveView does NOT check if leave_request.employee == request.user
          — A manager can currently approve their own leave request
          — Need to add: if leave_request.employee == request.user → reject with error

[MISSING] Manager delegate/proxy for approvals
          — PDF says: "If a manager is going on leave, they must assign someone 
            to handle approvals while they are away"
          — No delegate model, no delegate assignment endpoint, no delegate logic
          — Need: a DelegateApprover model or field on User/Department,
            an API to assign/remove delegate, and logic in approval views
            to allow the delegate to act on behalf of the manager

[MISSING] Employee sees rejection reason
          — LeaveRequestListSerializer (used by MyLeavesView) does NOT include
            'rejection_reason' field
          — PDF says: "Employee can see the updated status and any rejection reason"
          — Need to add 'rejection_reason' to LeaveRequestListSerializer fields

[MISSING] Manager should NOT be able to approve/reject requests for employees
          outside their managed department
          — Current check in ApproveLeaveView only verifies:
            employee_department.manager != request.user
          — But ManagerPendingLeavesView filters by employee__department=request.user.department
          — This means a manager of Dept A can see requests from Dept A but the check
            in ApproveLeaveView verifies if the employee's department's manager is the
            current user. This logic is correct but inconsistent:
            ManagerPendingLeavesView uses request.user.department (the manager's own dept)
            while ApproveLeaveView uses employee_department.manager (the dept's assigned manager)
          — If a manager is in Dept A but manages Dept B, the pending list shows Dept A
            employees, but approve/reject checks Dept B's manager.
          — The pending list should filter by departments WHERE the user is the manager,
            not by the user's own department.

[BUG]     ManagerPendingLeavesView filters by request.user.department
          — Should filter by departments where request.user is the manager:
            employee__department__manager=request.user
          — Current: employee__department=request.user.department
          — This would show ALL employees in the manager's own department,
            including requests from other employees that this manager doesn't manage
